### **產品需求文件 (Product Requirements Document - PRD)**

**1. 文件總覽**

  * **產品名稱**: Immersive Cyber-Maze (沉浸式賽博迷宮)
  * **版本**: 1.0
  * **日期**: 2025年7月16日
  * **作者**: Gemini
  * **狀態**: 定稿 (Based on user consensus)

**2. 產品願景與簡介**
本專案旨在打造一款基於 Web 的第一人稱 3D 迷宮遊戲。核心體驗是讓玩家在一個具有哥德式童話風格 (Gothic horror)、由程式自動生成的迷宮中探索。遊戲透過獨特的牆壁顏色標示系統，以及可選的導航輔助工具（足跡系統、小地圖），在提供挑戰的同時，也確保了流暢的遊玩體驗。

**3. 目標用戶**

  * 尋求快速、有趣網頁遊戲體驗的休閒玩家。
  * 喜歡解謎、探索和 3D 空間感的用戶。
  * 對歌德風感興趣的族群。

**4. 功能需求詳述**

-----

#### **4.1 核心遊戲流程**

| 階段 | 功能描述 | 細節規格 |
| :--- | :--- | :--- |
| **4.1.1 開始畫面** | 提供一個簡單的介面讓玩家開始遊戲。 | - 顯示遊戲標題 "Immersive Cyber-Maze"。 \<br\> - 包含一個「選擇難度」的區塊（如：按鈕或滑桿）。\<br\> - 一個醒目的「開始遊戲」按鈕。 |
| **4.1.2 難度選擇** | 玩家選擇的難度將決定迷宮的規模與複雜度。 | - **選項**: 提供至少三種難度：簡單 (Easy)、中等 (Medium)、困難 (Hard)。\<br\> - **對應**: 難度直接影響生成迷宮的尺寸（例如：簡單 15x15，中等 31x31，困難 51x51）。 |
| **4.1.3 迷宮生成** | 點擊「開始遊戲」後，系統在客戶端即時生成 3D 迷宮。 | - 採用**遞迴回溯法 (Recursive Backtracker)** 演算法生成迷宮的 2D 數據結構。\<br\> - 根據 2D 數據，在 3D 空間中渲染出牆壁與地面。 |
| **4.1.4 遊戲中** | 玩家以第一人稱視角在迷宮中探索。 | - **視角**: 第一人稱 (First-Person Perspective)。\<br\> - **移動**: 使用 `W` (前)、`A` (左)、`S` (後)、`D` (右) 鍵移動。\<br\> - **視角控制**: 使用滑鼠移動來控制視角方向。\<br\> - **物理碰撞**: 玩家無法穿透牆壁。牆壁為固定的物理邊界。 |
| **4.1.5 終點判定** | 系統自動檢測玩家是否到達終點。 | - **終點標示**: 迷宮的終點位置將放置一個**漂浮的獎盃**模型。\<br\> - **觸發**: 獎盃周圍有一個隱形的觸發區域，玩家進入該區域即判定為完成遊戲。 |
| **4.1.6 結算畫面** | 玩家到達終點後，彈出結算畫面。 | - 顯示祝賀訊息，如「恭喜通關！(Congratulations\!)」。\<br\> - 顯示本次遊戲的**總耗時**。\<br\> - 提供一個「重新開始」按鈕，點擊後返回「開始畫面」。 |

#### **4.2 視覺與美術風格**

| 功能 | 細節規格 |
| :--- | :--- |
| **4.2.1 牆壁視覺** | 牆壁是幫助玩家辨別方向的關鍵。 | - **主題**: 整體採用**賽博龐克 (Cyberpunk)** 風格。\<br\> - **調色盤**: 顏色從一個預設的賽博龐克調色盤中隨機選取，例如：亮洋紅、霓虹藍、電光綠、亮紫色等，搭配深色的背景（如深藍或黑色）。\<br\> - **顏色單位**: 牆壁的**每一個方塊單位**都應有各自獨立的隨機顏色。一面長牆將呈現為一條彩色帶。 |
| **4.2.2 終點標示** | 提供明確的視覺目標。 | - 模型：一個 3D 的、平滑著色的、有金屬質感的**漂浮獎盃**。\<br\> - 效果：獎盃可以帶有輕微的上下浮動動畫和微光效果，使其更醒目。 |

#### **4.3 使用者介面 (UI) 與抬頭顯示器 (HUD)**

| 功能 | 細節規格 |
| :--- | :--- |
| **4.3.1 計時器** | 記錄玩家的遊戲時間。 | - **格式**: `MM:SS:ms` (分鐘:秒:毫秒)，例如 `01:23:456`。\<br\> - **位置**: 顯示在遊戲畫面的固定位置（建議為頂部中央或角落）。\<br\> - **行為**: 從玩家在迷宮中獲得控制權時開始計時，直到到達終點為止。結算畫面也會顯示最終時間。 |
| **4.3.2 足跡系統開關** | 讓玩家可以選擇是否標記走過的路。 | - **UI**: 畫面上需有一個可點擊的圖標按鈕（例如：一個鞋印圖標）。\<br\> - **功能**: **預設關閉**。開啟後，玩家走過的地板方塊會改變顏色或紋理，形成一條足跡路徑。再次點擊可關閉此功能（路徑可選擇保留或消失）。 |
| **4.3.3 小地圖開關** | 提供一個可選的俯瞰視角地圖。 | - **UI**: 畫面上需有一個可點擊的圖標按鈕（例如：一個地圖圖標）。\<br\> - **功能**: **預設關閉**。開啟後，在畫面一角（建議為右上或左上）顯示一個 2D 俯瞰小地圖。\<br\> - **模式**: 採用「**戰爭迷霧**」模式，地圖上只顯示玩家已探索過的區域。\<br\> - **玩家標示**: 在小地圖上，需有一個**箭頭或三角形**圖標，即時顯示玩家的當前位置與**面向的方向**。 |

**5. 建議技術堆疊 (Tech Stack)**

  * **前端框架**: **React.js** - 利用其組件化的生態系來建構 UI 和遊戲邏輯。
  * **3D 渲染**: **`@react-three/fiber` (R3F)** - 在 React 中聲明式地使用 `three.js`，是實現 3D 場景的核心。
  * **3D 輔助工具**: **`@react-three/drei`** - 提供預製的相機控制器 (`PointerLockControls`)、模型載入器、以及性能優化工具。
  * **物理引擎**: **`@react-three/rapier`** - 用於實現高效能的 3D 物理碰撞偵測，確保牆壁的固體特性。
  * **狀態管理**: **`Zustand`** - 輕量級狀態管理器，非常適合用來管理遊戲狀態（如計時器、UI 開關狀態）和玩家輸入。
  * **部署平台**: Vercel, Netlify, GitHub Pages 等靜態網站託管服務。
